# 02 用户指南

> 文档角色：用户阅读。本文只说明你为什么使用 Asset Track、每月要做什么，以及遇到
> 问题时如何处理；技术实现请从[开发维护文档](00-reading-guide.md)进入。

## 先记住一件事

Asset Track 不要求你每天逐笔记账。它把账单整理放在每月集中完成：

```text
导入账单 → 处理少量异常 → 补充资产 → 完成对账 → 查看分析
```

你需要判断真正不确定的事情，系统负责重复的整理工作。

## 第一次使用

1. 在“设置 → 第三方插件 → 浏览”中搜索并安装 **Asset Track**。
2. 打开“设置 → Asset Track”。
3. 在当前 Vault 内选择一个专用数据目录。
4. 空目录点击“创建新数据库”；已有数据库点击“载入数据库”。
5. 从命令面板或功能区打开 Asset Track 编辑器。

2.0.0 要求 Obsidian 1.13.0 或更高版本。安装前请先升级到最新可用的 1.13.x 桌面版。
如果已有旧数据库，载入时插件会先检查是否需要升级到 schema 12；需要时请在设置中确认“保留并迁移”或“清除并迁移”。
插件不会静默升级，取消会保持原数据库不变。

## 每月结算怎么做

### 1. 收集账单

从本月使用过的支付平台导出账单，尽量确认每份账单的来源和覆盖日期。若有多个理财账户，
同时准备好本月加仓或提现分别对应的账户。

### 2. 导入账单

在“记录 → 流水”子页面顶部点击“导入账单”，选择文件后依次确认文件结构、字段映射和预览结果。
支持 CSV、XLSX 和 XLS。
流水按“出账（支出）/入账（收入、代付）/理财（加仓、提现）”分 Tab；出账和入账还可切换逐项、按商品汇总、按交易对手汇总。
这里的“代付”指代付回款：钱回到你这里，但不是收入，而是冲减之前由你暂时承担的消费。

### 3. 处理需要判断的问题

检查商品-分类冲突、空商品、日期或金额异常。稳定重复的商品分类可以交给规则；不确定的项目留给自己判断。

需要给跨分类的一组流水做主题标记时，在“配置 → 分类属性”右侧先创建标签，再在出账或入账的
逐项流水表点击“编辑”打开标签弹窗。理财流水不显示标签入口。
标签可以多选；商品或交易对手汇总中选择多笔流水后，可以预览添加、移除或替换标签。标签只在点击
“保存流水”后写入，导入和匹配规则不会自动打标签。

### 4. 补充月末状态

在“记录”主页面的第二层导航中，分别打开“资产账户”“借款”和“固定资产”，更新月底状态。资金账户的新增与管理在设置中完成。
理财流水中的加仓和提现可以在“账户”列选择对应的理财账户，便于月度分析按账户查看。
上月未还的借款会自动出现在后续月份；在哪个月还清，就在那个月勾选“本月还清”。
借款用于记录人与人之间尚未结清的纯资金关系：我借入表示待偿还，我借出表示待收回。

### 5. 完成检查

各子页在页面顶部分别点击对应的“保存资产”“保存借款”或“保存固定资产”；流水导入和规则处理后
点击“保存流水”。保存当前区块不会改写其他区块。切换主 tab、记录/配置子页面、月份或创建月份时，
如果当前页面有未保存修改，系统会先提示保存或放弃。随后查看未处理问题和对账差额；差额是
排查线索，可能来自漏导账单、漏记收入、类型选择错误或资产状态未更新。

### 6. 查看结果

确认本月已经整理完成后，再到“分析”查看消费结构、资产变化、周期支出和长期趋势。

## 导入账单的最短路径

1. 选择账单文件；
2. 确认日期、商品、金额和收支对应的字段；
3. 查看接受、忽略和异常记录；如果有被过滤的行，展开“查看全部被过滤条目”逐行核对原始数据和过滤原因；
4. 应用到草稿；
5. 点击“保存流水”。

系统会记住常用的字段、收支值和状态选择，下次导入时自动预填，但每次仍会保留预览
供你确认。接受流水加入当前草稿后才会保存本次映射；如果映射保存失败，已加入的流水不会
撤回，界面会提示“流水已加入，但映射未保存”，下一次导入仍可重新确认。

### 导入时需要知道的几件事

- 没有日期或日期为空时，记录会暂时使用所选月份的第一天；
- 日期按行独立解析，同一份账单可以混用 `YYYY-MM-DD`、`M/D/YYYY`、`M/D/YY`、中文年月日、`YYYYMMDD`、Excel 日期序列和带时间的日期值；
- 无法识别的日期、金额或收支类型会被标为无效；
- 空商品、零金额和缺少分类通常会作为提醒保留，方便之后处理；
- 质检结果只显示在“流水”子页面；错误或提醒会标在对应行号旁，保存后若仍有不规范流水，
  系统只用消息提示你回到出账、入账或理财区检查行号标记；
- 增量导入不会自动去重。重复导入同一份账单或重叠日期范围，可能产生重复流水；
- 覆盖当前月份只替换流水，不会替换现金、理财或固定资产；
- 原始账单不会被保存到插件设置中。

如果导入预览中的记录数量或日期范围不对，先不要应用，返回检查文件和字段选择。

确认账单字段映射后，“应用到草稿”只把接受行放入当前草稿，不会再打开通用的“流水操作预览”窗口，
也不会在导入链路中自动执行规则。预览会同时列出所有接受行和被过滤的原始行（跨月、状态过滤、忽略类型或无效字段），
便于发现漏导记录；来源文件也会随新流水保留。进入草稿后可手工补分类或纠错；如需批量应用规则，
请在流水区单独点击“应用规则”并确认，再保存最终草稿。

## 分类、属性、标签、规则和冲突

规则用于减少重复分类，不会替你静默修改历史流水。配置下的“数据健康”会直接打开商品-分类冲突表，
不再通过多个问题框分流；点击具体商品后，可编辑商品名称或迁移历史分类。

- 稳定、重复的商品可以创建规则；
- 同一商品出现多个分类时，先查看冲突再处理；
- 批量统一商品或迁移分类前，系统会先显示影响范围；
- 确认后才会写入，取消不会改变已有记录；
- 不确定的流水可以暂时保留，优先处理真正影响本月结算的问题。

分类回答“这笔流水属于哪类收支”；属性描述分类，例如必要、周期和大额；标签描述具体流水主题，
例如旅行。每个属性组对一个分类最多选择一个选项，一笔流水可以有多个标签。月度和年度分析会分别
展示分类、属性和标签，标签金额允许重叠，不能把标签金额相加。

分类表中的名称、定义说明、收支类型和颜色可以直接修改；点击“编辑”主要处理分类属性、迁移历史流水或移除分类。
“配置 → 分类属性”是一个左右分栏页面：左侧管理属性组和属性值，右侧管理流水标签。每个区域都有自己的“新增”和“保存”按钮，保存属性不会提交标签草稿，反之亦然；切换配置子页或离开页面时，如有未保存修改会提示保存或放弃。移除已有引用时在窗口内确认清理或转移，弹窗会明确说明原有属性或标签将转移到哪个定义，确认内容不展示 sha、完整路径、月份等内部明细。
已有标签的流水点击“编辑标签”时，弹窗标题会显示为“编辑 <商品> 的标签”，并预先勾选当前标签；取消不会改变草稿，应用后仍需点击“保存流水”。
月度分析点击分类、属性或标签的相关流水会弹出只读明细，按日期、商品、交易对手、分类、金额展示；
收入分析逐笔列出收入项目、分类和金额，年度分类成本只展示图表。

“配置 → 商品总览”默认查看最近 1 年的商品或交易对手金额、次数和日期变化；可以用起止日期控件自行扩大范围。
点击一行的“编辑”后，可在窗口的不同标签页修改商品或交易对手名称、历史分类及规则，所有相关流水都在窗口内展示；
“配置 → 匹配规则”维护三种精确规则：仅商品、仅交易对手、交易对手 + 商品。固定优先级是
“交易对手 + 商品 ＞ 商品 ＞ 交易对手”，同一条流水只采用一条规则；规则修改不会自动回写历史。
规则列表上方可以直接按搜索、收支、状态、作用域和分类筛选，也可以分组或排序；这些操作只改变当前浏览，不会修改规则。

选择流水后，应用规则会在确认必要的覆盖风险后直接进入当前草稿，不再打开单独的规则预览页面；
其他批量修改仍会在同一个编辑窗口中显示简要前后对比，确认后进入当前草稿。
单笔流水可创建规则，收入和代付可以互相转换，代付也允许使用支出类分类并参与 AI 分类。确认只会把结果放入当前草稿，仍需点击“保存流水”；操作审计
仍保存在本地数据库，但不再在流水页提供单独的操作记录按钮。

按商品或交易对手汇总时，母行中的商品/交易对手也是输入框。修改母行会把该汇总组内
相同字段的逐笔流水一起改入当前草稿；展开后仍可单独改某一笔。

一个实用技巧：先导入一个完整月份，再切到商品汇总或交易对手汇总，并按出现次数排序。
重复出现的商品、商户和代付回款通常最适合创建规则。连续整理几个月后，你会形成自己的
稳定规则集，之后每次导入需要手工判断的项目会明显减少，账单也更容易变成可解释的资产
流向记录。

## 分析怎么看

- **年度**：查看年末资产、长期趋势、周期消费和当年出现过的固定资产；
- **月度**：查看当月分类变化、异常和大额流水，并按理财账户查看本金、资金流、市值、流动资金、仓位和收益率；

“记录”用于编辑事实，“配置”用于维护分类、规则和历史冲突；分析只读取已经保存的数据。

收入和资产增长、支出和资产下降使用不同颜色表示。分析数字来自已经保存的月度数据，
不是独立维护的另一份账本。

## 备份与恢复

- 重要修改前，在设置中导出一份完整备份；
- 备份应放在 Vault 或仓库之外的安全位置；
- 恢复前系统会先检查备份，确认后才替换当前数据；
- 恢复或切换数据目录前会保留当前数据的保护快照；
- 禁用或卸载插件不会删除数据库和备份。

Asset Track 不执行定时云备份。是否备份、备份到哪里、何时恢复，都由你决定。

## Obsidian 文件系统访问警告

如果你在 Obsidian 社区插件页面看到 **Direct Filesystem Access** 警告，可以按下面的
边界理解：

- 这个警告来自 Asset Track 使用桌面 SQLite 和本地文件操作；
- 这些操作用于创建数据库、维护 SQLite 文件、迁移前保护快照、恢复前安全快照、手动备份导出和备份恢复；
- 正常运行时，数据库固定在你选择的 Vault 内数据目录：`<数据目录>/accounting_system.db`；
- 自动保护快照固定在 `<数据目录>/backups/`；
- 插件不会扫描整个 Vault 或系统文件，也不会恶意读写无关文件；
- 只有当你主动选择备份导出目录或恢复文件时，插件才会接触该路径。

因此，这个警告说明的是“插件具备本地文件访问能力”，不是 Asset Track 会静默读取或上传
你的文件。Asset Track 仍然不要求账户、不含遥测；未配置 AI 时不联网。

## 语言与隐私

界面会跟随当前 Obsidian 语言。中文环境显示中文，其他语言显示英文；账户、分类、
商品和流水说明等你创建的内容保持原文。

数据保存在你选择的 Vault 内目录中。插件不要求账户、不包含遥测。未配置 AI 时不联网；
如果主动启用 AI，只有选中的可分类流水和完成分类所需的分类定义会发送到你配置的 API，
API Key 只存放在 Obsidian SecretStorage，不写入设置、数据库、日志或请求正文，也不会枚举 Vault 中的其他文件。

## 遇到问题时

- **看不到数据**：检查是否选择了正确的数据目录，再重新载入数据库；
- **导入数量不对**：回到预览检查日期、状态和收支字段；
- **出现对账差额**：先检查账单是否完整，再检查资产、流水页中的借款区块、理财和特殊流水；
- **修改被拒绝**：先重新加载当前月份，确认没有其他窗口刚刚保存同一内容；
- **插件提示版本过低**：升级到最新可用的 Obsidian 1.13.x 桌面版。

开发、测试、财务公式、数据可信性和发布门禁不放在用户指南中，请从
[文档阅读指南](00-reading-guide.md)进入维护文档。
