# 02 用户指南

## v1.2.0 快速说明

设置页的“显示与分析”区域可选择基础货币、标准或会计金额格式、平账容差和大额
支出阈值。资产分析同时显示资金投入资产与市场净资产；年度页的周期消费表汇总
最近 12 个有数据月份中标记为“周期”的支出分类，并按商品合并。

## 界面语言

Asset Track 自动跟随当前 Obsidian 语言。中文语言代码（包括 `zh-CN`、`zh-TW`
及其他 `zh-*` 变体）显示中文，其他语言显示英文。修改 Obsidian 语言后重新加载
插件或重启应用即可。

切换界面语言不会修改数据库。账户名、分类名、交易对方、商品和流水说明等用户内容
始终保持录入时的原文。

## 首次使用

Asset Track 已通过 Community Plugins 审核。推荐打开“设置 → 第三方插件 →
浏览”，搜索并安装 **Asset Track**，然后启用插件。

社区目录不可用时，可从同一个 GitHub Release 下载 `main.js`、`manifest.json`
和 `styles.css`，放入 Vault 的 `.obsidian/plugins/asset-track/` 后启用。不要
使用 GitHub 自动生成的源码压缩包。

安装完成后：

1. 启用 Asset Track。
2. 打开“设置 → Asset Track”。
3. 在“Asset-track 数据目录”中输入关键词，从 Vault 文件夹联想列表选择目录。
4. 空目录点击“创建新数据库”；目录中已有有效的 `accounting_system.db` 时点击
   “载入数据库”。输入路径本身不会创建或修改文件。
5. 数据库直接位于 `<数据目录>/accounting_system.db`；完成前 ItemView 只显示
   配置引导，不访问财务数据。

## 日常使用

- “分析”：Home、年度、月度实时图表。
- “流水”：现金、理财、支出、收入、代付、加仓、提现和固定资产。
- “借款”：维护发生日期、金额、是否还清和还清日期。
- “规则”：在分类定义、已保存匹配规则、推荐分类规则和历史商品统计四张表中维护规则。

正向增长和收入显示为红色，下降和支出显示为绿色。

月度分析的“分类与上月对比”把分类增减额写在分类名称旁，上月和本月实际金额
写在各自柱形右侧，不需要再对照图外标签。“异常与变化”把同一分类相对上月和
近三月均值的变化合并在一行，较长说明会在单元格内自动换行；“大额支出”只列
商品和金额。顶部“对账差额”卡片只显示差额金额，并标记为“多消费少支出”、
“少消费多支出”或“平账”。差额绝对值小于 100 元时视为平账。

## 导入账单

在“流水”的月份编辑器顶部点击“导入账单”。支持 CSV、XLSX 和 XLS，Excel
工作簿读取第一个工作表，单个文件最大 20 MiB。建议先按真实账单整理列名、账单范围和明显无关记录，
再进入映射窗口：

1. 选择“增量导入（追加全部）”或“覆盖当前月份”。
2. 选择日期、商品/说明、金额和收支方向对应的原始列；没有日期列时选择“当前月 1 日”，交易对方可选。
3. 把原始收支值逐一映射为支出、收入、代付、加仓、提现或忽略。
4. 可选映射分类和交易状态；选择状态列后，界面列出文件中的真实状态值，空值显示为
   “（空状态）”，新映射默认勾选空状态，仍可取消。
5. 生成预览，确认接受、日期默认值、跨月、状态过滤、忽略和无效行数量及示例。
6. 应用到草稿，最后点击“保存月份”才写入数据库。

增量导入不执行去重。重复选择同一个文件或导入范围重叠的多份账单，会再次追加
所有有效记录；账单范围由用户自行控制。覆盖模式只替换流水草稿，不影响现金、
理财和固定资产。

同一种表头的列映射、收支值映射和状态过滤会被记住；下次自动预填，但仍显示
预览供确认。原始账单内容不会保存到插件设置。

如果映射保存失败，当前草稿不会被部分修改，导入窗口会保留供重试；重试不会因为
上一次失败而重复追加流水。

现有 3–5 列简化格式继续作为内置映射模板：

| 表头 | 是否必需 | 说明 |
| --- | --- | --- |
| `商品` | 必需 | 流水说明；为空时仍可导入并在保存时显示警告 |
| `交易对方` | 可选 | 商户、收款方或付款方，可与商品共同用于规则匹配 |
| `收支` | 必需 | 只能是 `支出`、`收入`、`代付`、`加仓`、`提现` |
| `金额` | 必需 | 数字；允许千分位逗号和 `¥`，程序按绝对值读取；零金额保留并显示警告 |
| `日期` | 可选 | 建议使用 `YYYY-MM-DD`；缺少列或空单元格时预览默认使用当前月份 1 日，非空异常日期为无效 |
| `分类` | 可选 | 使用现有分类名称精确匹配；缺少或不匹配时保存为警告 |

最小三列表头：

```csv
商品,收支,金额
午餐,支出,35.5
工资,收入,"10,000"
```

带日期和分类的五列示例：

```csv
商品,收支,金额,日期,分类
午餐,支出,35.5,2026-07-02,餐饮基础
工资,收入,"10,000",2026-07-01,工资收入
```

没有日期时使用当前月份 1 日。导入始终逐项保留，不按商品合并。备份内部文件
不应作为普通月度账单导入。

流水区域可以在“逐项”和“按商品汇总”之间切换。逐项表按流水类型分别编号，
在自身滚动容器内只渲染当前可视行。汇总只影响查看，显示次数、总金额、日期范围和
分类冲突；展开后仍编辑原始流水。缺少分类、空商品和零金额属于可安全保存的警告；
无法解析日期、金额或收支类型仍会阻止保存。保存后重新打开月份会重新显示这些警告，
不新增数据库状态，“暂存”仍使用现有 `saved` 状态。

## 规则中心

规则页固定显示四张可独立排序、滚动的表格：

1. **分类定义**：维护收支分类及其属性。
2. **已保存匹配规则**：查看交易对方/商品规则、历史覆盖、重复和冲突状态。
3. **推荐分类规则**：按全部已保存月份中达到次数阈值且尚未覆盖的交易组合推荐分类。
   历史分类冲突时必须手动选择分类；创建规则需要 revision 一致，且不会改写历史账单。
4. **历史商品统计**：显示出现次数、月份数、总/平均/最近金额、最近日期、分类置信度和
   规则覆盖状态；“打开最近月份”可回到原账单修正后再应用规则。

## 备份与恢复

插件不执行自动备份。

- “立即备份”先选择目录，再生成一个完整 ZIP。
- 恢复时选择完整备份 zip 或 SQLite 数据库文件。
- 切换数据目录和恢复前的保护快照统一保存在当前 `<数据目录>/backups/`。
- 恢复候选通过系统文件选择器选择，不需要手工输入路径；选择后自动校验。
- 候选数据必须先通过完整性和内容一致性校验。
- 替换数据库前会创建当前数据安全快照。

重要修改前应手动备份，并把重要备份复制到 Vault 或仓库之外。

新数据库只创建“默认现金账户”和“默认理财账户”。恢复数据时以备份中的账户
定义为准；已有账户不会被自动删除或停用。

## 安装环境

当前插件包含 React/Recharts 和 TypeScript `node:sqlite` 数据层，运行时不要求
用户安装 Node、Python、uv 或虚拟环境，也不区分 CPU 架构。需要 Obsidian
1.9.10 或更高版本及对应的新版桌面安装器；旧安装器缺少 SQLite API 时，插件会在
用户初始化或打开面板时提示升级，不会修改数据库。
