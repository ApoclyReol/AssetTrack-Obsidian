# 09 路线图

面板、自动中英文界面与规则工作台，并完成 Obsidian 1.13 兼容升级：

- TypeScript Service/Repository 和 `node:sqlite`；
- schema 10，包含 schema 9→10 保护备份迁移、理财流水账户、通用规则、流水来源和操作日志；
- 标准三文件、跨 CPU 架构产物；
- 月份事务、revision、计算、CSV/XLSX/XLS、规则、账户和备份恢复测试。
- 路径与 schema 结构校验、失败导入原子性、可访问弹窗和可视行渲染。
- 中文环境显示中文，其他语言回退英文；用户内容和数据库规范值保持不变。
- 全部金额统一格式化，平账和大额阈值可配置；
- 对账使用资金投入资产，财富趋势并列展示市场净资产；
- 年度页按商品汇总最近 12 个有数据月份的周期消费。
- 导入容错、月流水警告保存、商品历史/分类回溯、规则命中解释和商品名称统一；
- 分类与规则分别保存，普通表格统一表头、字号、对齐、列宽和窄窗口换行；
- 规则实际覆盖与重复条件/重写链校验分离，部分覆盖商品仍可处理未覆盖流水；
- ItemView 关闭时取消放弃可在当前会话恢复月流水、月内借款、分类和规则草稿。
- 借款整合到月流水页，继承、当月新增、当月还清和实时对账差额来自同一借款事实。
- 特殊流水不显示分类列；商品汇总移除最近日期并支持收支和分类排序。
- 设置页改用 `getSettingDefinitions()` 和原生目录控件；插件代码不再枚举 Vault 全部文件。
- 最低 Obsidian 版本提升至 1.13.0，发布声明要求使用当前最新的 1.13.x 桌面版。

## 产品路线优先级

后续路线不以“增加更多手工记账功能”为默认方向，而以月度结算链路的完整性、唯一
事实和可验证性排序。

规则泛化、流水三类业务 Tab、商品/交易对手汇总和批量操作均已完成当前版本的实现；
P3 代付关系模型仍是未来设计。

### 已完成：理财账户的本金调整后收益

月度理财账户现在以月末快照展示本金、市值、流动资金和仓位，但收益率和“对比上月”会
先进行资金流调整：

- 调整后市值 = 月末仓位 − 本月加仓 + 本月提现；
- 调整后本金 = 月末本金 − 本月加仓 + 本月提现；
- 收益率 = (调整后市值 − 调整后本金) / 调整后本金；
- 环比金额使用调整后市值与上月月末仓位比较，提现金额会加回；上月收益率也使用上月的
  同一口径。

当前按月结算，不按交易日加权；交易日期加权收益 attribution 留作后续独立议题。

### P0：把月度结算做成清晰工作流

- 流水页顶部显示本月状态、保存警告、对账差额和下一步操作，但不新增独立顶层工作台。
- 借款整合到月流水页：自动继承上月未还，用户在对应月份新增借款或勾选本月还清，
  底层仍使用 `debt_manager` 事实表。
- 保存警告可定位到具体区块和行号，优先处理未分类、规则未命中、对账差额和特殊交易遗漏。
- 配置中心继续承担跨月商品、分类和规则治理；规则不是每月必经流程。

### P1：让唯一事实层更可解释

- 所有分析指标统一调用领域查询，并可以下钻到分类、商品、流水和规则治理入口。
- 分析首页改为结论优先：先显示最近月平账状态、收入、净支出、资产和主要异常。
- 稳定的只读查询接口和回溯路径，保证月度、年度、商品、资产分析不产生第二套统计口径。
- 在不改变 SQLite 事实层前提下扩展支付平台导入模板。

### P2：把结算结果转化为长期价值

- 滚动十二个月趋势、周期支出识别和资产积累结构。
- 月度异常解释、可追溯的月报和年度报告，以及可嵌入 Obsidian 的只读结果。
- AI 仅作为字段映射、商品归一化、异常解释和月度摘要的建议层；最终事实仍由用户确认。

### 明确降级或排除的方向

- 高频快速记账、每日预算、实时余额提醒和连续打卡不占据主路线。
- 不引入云端银行同步、多用户服务或把支付平台适配拆成独立事实模型。
- 不让 Markdown、图表、缓存、导出或 AI 生成内容形成第二套财务账本。

## 工程性路线

- v1.7.0 实现阶段已完成两轮职责拆分：分析页面、月度编辑区块、分类/匹配规则表、数据健康、
  商品统一和规则创建均有独立 UI 模块；`AssetTrackEditorApp.tsx` 保留页面路由，月份和规则编辑器
  分别保留各自的草稿、dirty、revision 与事务协调。后续只在边界稳定、能降低耦合时继续拆分，
  不为目录层级而重排代码。
- Repository 已完成第一轮读写拆分：`AssetTrackRepository.ts` 保留兼容 facade，写入职责位于
  `monthWriteRepository.ts`、`configurationWriteRepository.ts` 和 `historyWriteRepository.ts`，
  规则读取位于 `ruleReportReadModel.ts` 与 `productHistoryReadModel.ts`，由
  `ruleHistoryReadModel.ts` 协调跨模型汇总。所有拆分保持 Service/Repository 接口、revision 校验
  和单事务写入行为不变；后续只在测试或业务边界继续增长时再拆分。
- 将 CSV/XLSX/XLS 解析真正迁入 Worker；当前版本仍只完成 `ArrayBuffer` 读取并移除
  Data URL/Base64 中间副本。
- 将现有中文错误文本和 `t("中文", "English")` 逐步迁移为稳定消息键与完整
  `AssetTrackError { code, params, status, cause }`，测试只依赖错误代码。
- 大数据量分析的分片、缓存和真实 Vault 性能采样；
- 自动化 Electron/Obsidian 三平台 smoke；
- 移动端仅作为独立长期研究，不纳入当前桌面版路线。
