# 05 Asset Track 设计系统

本文档定义长期视觉与交互边界，不记录某一次页面微调或临时 CSS 修复。界面应像一个安静、可信、
适合长期复盘的 Obsidian 桌面插件，而不是营销页面。

## 1. 设计原则

- 先呈现用户需要判断的数据，再展示解释性细节。
- 颜色表达财务语义，不用颜色装饰或制造错误的好坏暗示。
- 图表只回答一个问题；无法帮助判断的图表应删除或折叠。
- 复杂数据表默认折叠或限定在自身滚动容器内。
- 用户操作必须有明确的加载、成功、失败和空状态。
- 原生 App 的窗口、滚动、hover 和 tooltip 应稳定，不追随鼠标抖动。

## 2. 视觉令牌

当前实现主要位于根目录 `styles.css`，修改令牌时应同步本文件。

| 令牌 | 当前用途 | Obsidian 映射 |
| --- | --- | --- |
| `--asset-track-inflow` | 收入、资产正增长 | `--color-red` |
| `--asset-track-outflow` | 支出、资产负增长 | `--color-green` |
| `--asset-track-cash` | 现金图表 | `--color-yellow` |
| `--asset-track-investment` | 理财本金图表 | `--color-blue` |
| `--asset-track-total-assets` | 总资产图表 | `--color-purple` |
| `--asset-track-chart-1..10` | 饼图稳定色序 | Obsidian 语义色和强调色 |

固定语义：收入红色、支出绿色、现金金色、理财投入蓝色、总资产紫色。图表、指标、表格和 hover 提示必须一致。

## 3. 布局与响应式

- 顶部工具栏保持可见，分析、流水、借款和规则使用同一个 ItemView。
- 卡片和网格子项必须允许 `min-width: 0`，长表只能在内部横向滚动。
- 月度正文顺序固定为现金与理财、流水编辑、固定资产、月度总览。
- 月度和年度复杂审计表默认折叠，打开后不能把整个页面撑出窗口。
- 窄窗口下工具栏纵向排列，分析卡片、映射和账户网格转为单列。
- 大流水逐项表固定在自身滚动容器中，只渲染当前可视行和少量 overscan。

## 4. 图表规范

每张图表先写清楚它回答的问题：趋势、分布、排行或组成，只保留能支持判断的系列。

- 收入系列使用红色，支出系列使用绿色。
- 总资产趋势只使用现金、借款和理财投入本金；不把理财市值或固定资产混入。
- 年度页使用近 12 个月窗口；图中的每根储蓄率柱仍按单月口径计算，正值红色，负值绿色。
- 缺失、零值和未来月份必须有可区分的展示方式。
- 坐标轴、图例、tooltip 顺序保持稳定；tooltip 不应捕获鼠标事件或触发布局变化。
- 不使用彩虹色、无意义渐变或重复绘制。
- 月度分类环比使用单张横向图：分类名称旁显示增减额，柱形右侧显示上月和本月
  实际金额，不再在图外重复列出变化。
- 月度异常表只显示分类、当前金额和合并后的异常说明；大额支出使用更窄的商品、
  金额两列表。大额表展示事实，异常表解释达到规则阈值的变化。
- 异常表采用固定列宽，单元格内容居中，长异常说明必须自动换行，不以横向滚动
  作为默认阅读方式。
- 月度对账作为顶部指标卡紧跟资产环比：对账差额使用指标大字，流水净支出、
  理论净支出和解释不在卡片中重复展示，只保留简短的差额状态；绝对值小于
  100 元统一显示为平账。

## 5. 编辑器与反馈

- 服务端响应是权威数据；未保存内容只保留在当前 React 编辑会话。
- 普通单元格编辑保留编辑器和滚动状态；新增、删除、导入、规则预览和保存后重载清理旧控件状态。
- “导入账单”是可见的主操作按钮；文件选择器可以隐藏，但不能让隐藏 input 的
  `label` 代替按钮承担主要视觉入口。
- 账单映射使用明确的模态窗口，增量和覆盖模式必须并列展示；增量模式始终显示
  “不去重”警告，预览同时给出接受、日期默认值、跨月、状态过滤、忽略和无效行数量及示例；
  空状态必须可见且可勾选。
- 流水“逐项/按商品汇总”切换不改变草稿事实；汇总行展开后编辑的仍是对应原始
  流水，分类冲突必须显式标记。
- 保存按钮必须显示 pending、success、error 三态；成功文案应说明“已保存”，不能只改变按钮颜色。
- 结构变化不能按旧行号重放编辑；使用持久化 `id` 或固定资产 `asset_key`。
- 离开有 dirty 草稿的页面、月份或数据目录前必须询问用户。关闭 ItemView 时若用户取消
  放弃，应在当前插件会话中重新打开并恢复完整草稿；恢复过程不得把草稿持久化到设置或
  workspace layout，外部 revision 变化必须继续可见。

## 6. 空、错和等待状态

- 加载：使用稳定的占位或 spinner，不反复跳动内容高度。
- Obsidian 加载插件时不显示 Asset Track 全局准备提示；用户打开编辑面板后等待
  超过约 500ms，才在面板内部显示准备状态。
- 空数据：说明为什么为空以及下一步操作，不用错误红色。
- 校验错误：指出级别、字段、行和修复方式；错误阻止保存，警告随流水保存并在重开月份时恢复，
  不只显示异常堆栈。
- 保存失败：保留当前草稿，明确提示重试或刷新，不静默回退服务端数据。
- 数据库不可用：显示可执行的错误说明与“重新打开数据库连接”入口，不显示裸异常。

设置页中的初始化、备份、恢复和诊断只在对应设置区域展示进度和结果。系统文件选择器
取消选择属于正常退出，不显示错误，也不触发 API。理财账户使用独立响应式网格，
账户名、本金、市值和流动现金输入框保持同一基线，窄窗口改为纵向换行。

规则页的分类定义、已保存匹配规则和健康问题面板必须使用独立的内部滚动容器、现有排序按钮、
加载/空状态和中英文无障碍文本。健康摘要点击后显示商品/分类冲突、规则冲突或无规则商品视图；商品/分类冲突
默认显示分类冲突，问题面板不显示通用筛选区，不提供“加载统计”按钮。点击具体商品才打开浮动
回溯 Modal；商品编辑 Modal 默认按收支和主要分类加载，可切换分类、搜索并批量统一多个商品组；
选择全部分类时必须先输入商品搜索。分类迁移 Modal 则直接加载指定分类下的商品，
不显示通用筛选区。三种处理流程都使用固定宽度的目标分类/商品输入框、明确的选择状态和预览确认流程。
规则层级只在后台解析，规则条件只填写交易对方和商品字段，系统根据填写情况自动决定匹配方式。分类定义不提供启停开关，也不显示商品冲突；
删除前必须没有历史流水和规则引用，删除失败和确认均使用原生 Modal。历史统计只读已保存月份；不再提供
打开最近月份的导航按钮。筛选网格、Modal、表格和复选框必须设置 `min-width: 0`、合理的最大宽度与固定复选框尺寸，
长文本自动换行，避免控件重叠、缩成竖线或制造不必要的横向滚动。

所有数据表遵循统一排版：所有可见表头使用按钮式视觉，实际可排序表头使用按钮交互，非排序表头使用
`aria-disabled` 的不可交互按钮语义；操作列也使用统一的“操作”不可交互按钮表头；
正文使用略小于表头的 UI 字号，表头和单元格统一上下居中。商品、交易对方、分类和说明左对齐，日期、收支、
状态、统计数量、复选框和颜色居中，金额和价格右对齐。

### 表格响应式规范

以“分析 → Home → 固定资产摘要”的表现为所有表格基准：

| 项目 | 规范 |
| --- | --- |
| 外层容器 | 使用 `.asset-track-table-scroll`；允许纵向滚动，禁止表格自身横向滚动 |
| 表格尺寸 | `width: 100%`、`max-width: 100%`、`min-width: 0`、`table-layout: fixed` |
| 单元格 | `white-space: normal`、`overflow-wrap: anywhere`、`word-break: break-word`，长文本换行 |
| 列宽 | 只提供语义列宽提示，不设置 960px、1040px、1080px 等表格级最小宽度 |
| 窄窗口 | 保持表头和内容可见，通过换行和省略适配，不要求用户横向滚动 |
| 流水编辑网格 | 使用同样的 `width: 100%` 和 `min-width: 0`；网格列按比例收缩，仅保留纵向虚拟滚动 |

规则工作台、历史商品、冲突处理、商品总览和流水表都必须遵守这套规则。规则工作台的分类表只保留流水数一个历史统计列，
商品冲突表把交易对方数、月份数和金额统计移至分析页商品总览；商品总览只展示分类、交易统计和金额统计，
不重复展示规则健康信息。分类表的大额、颜色和流水数使用紧凑语义列宽，操作按钮沿用通用操作列的满宽按钮样式；
商品总览的数量/状态/日期居中、金额右对齐，表体使用与其他分析表一致的次级背景。

## 7. 图标和资源

- App 图标必须是带 Alpha 通道的 RGBA PNG；透明四角不能烘焙为黑色。
- 修改源图后必须重新生成 `.icns`，并用 `sips` 或 `iconutil` 抽检透明通道。
- 资源应保持低频、稳定和可重建；不把个人截图、运行日志或构建缓存放入资源目录。

## 8. 维护规则

新增组件前先复用现有 panel、button、table、notice 和 token。改变布局、颜色、图表口径、tooltip、
hover 或窗口行为时，必须同时更新本文件、相关 PRD/用户指南和前端构建验证。

## 9. 当前金额、资产与表格展示（v1.4.0）

- 所有金额由统一 `Intl.NumberFormat` 模块显示，业务组件不得拼接货币符号。
- 财富趋势以市场净资产为主线，并同时展示资金投入资产；固定资产不进入任一口径。
- 平账和大额标签必须使用当前插件设置，不在组件中复制默认阈值。
- 周期消费表保持只读，提供商品、金额和日期排序，并在自身滚动容器中展示。
- 所有普通表格的表头使用统一按钮式视觉；操作列使用“操作 / Actions”不可排序表头，
  正文采用略小于表头的 UI 字号且上下居中。
