# Release v2.0.0

> 状态：已发布（2026-10-01）；tag 为 `2.0.0`，GitHub Release 已创建并上传标准三文件。

v2.0.0 将流水标签和分类属性从分类旧字段中拆出，升级到 schema 12。分类继续表示流水所属的
收支类型；属性描述分类特征；标签描述跨分类的具体流水主题。资产、对账、储蓄率和收支公式保持
现行口径。

对用户最重要的提示：已有 schema 9/10/11 数据库首次载入时可能需要升级。插件会先显示影响并等待
用户在“设置 → Asset Track”确认“保留并迁移”或“清除并迁移”，不会静默修改；确认后才创建保护备份并
执行升级，取消不会修改原文件。

## 用户可见变化

- 配置页新增属性组、属性选项和标签管理。属性组和属性值按左栏展示，标签表在右栏并排；
  两栏分别保存，移除已引用定义
  时在弹窗选择转移或清理；每次历史关联保存前只创建一次保护快照。
- 分类定义按属性组选择选项，每组最多一项。必要性、消费频率和大额不再是分类字段。
- 出账、入账流水通过独立弹窗编辑标签；逐项、商品汇总和交易对手汇总支持标签添加、移除、替换
  的预览与确认。标签只进入当前月份草稿，保存时随同月份事务和操作日志写入。
- 月度和年度支出结构提供分类、属性、标签三个视角。标签允许重叠统计，界面明确提示标签金额不可
  相加推导总支出。月度分析用只读弹窗查看相关流水，年度分类成本不显示跳转按钮；没有属性或标签是正常空状态。
- 移除大额支出金额阈值，历史分类大额标记由迁移后的“支出规模 → 大额”属性承接。
- 分类、属性组、标签、商品总览和数据健康的表格行收束为单个编辑入口；编辑窗口内切换名称、分类和历史迁移，并在同一窗口内二次确认移除。逐项流水恢复交易对手列，规则独立显示；月度分析新增收入明细，与紧凑的异常区并排。
- X1 体验修正将属性和流水标签合并为同一配置页的左右分栏，同时保留独立保存边界；分类名称、
  收支类型和颜色可在分类表中直接编辑。流水标签弹窗显示“编辑 <商品> 的标签”并加载已有选择；
  移除确认只保留用户需要决定的清理/转移动作，不展示 sha、完整路径和月份等内部明细。
- 发布前收尾修正：导入映射未完成的必填字段会红色强调并阻止生成预览；手工编辑商品或交易对手后应用规则会基于当前草稿重新匹配，保留未保存修改并重建操作日志状态；数据健康和商品总览操作列在多行布局下保持对齐，属性/标签移除文案明确原有定义的转移目标。

## 数据兼容与迁移

- schema 12 新增 `attribute_groups`、`attribute_options`、`category_attributes`、`tags`、
  `transaction_tags` 五张表，关联使用稳定 key 和外键。
- schema 9、10、11 首次打开时先只读展示迁移影响。用户可以选择保留旧属性、清除旧属性或取消；
  取消保持旧数据库未打开、未修改。确认后才创建 `before-schema12-*.db` 保护备份，并在同一事务中
  执行 9→10→11→12 链、校验关联和完整性，失败自动回滚。
- 新库预置可删除的必要性、消费频率、支出规模属性组和“旅行”标签。备份格式升级为 9，包含五张
  taxonomy 表；旧格式 8 的 schema 11 完整备份仍可只读校验并通过临时迁移副本恢复，失败不会覆盖
  当前数据库。

## 发布执行边界

- 提交标题使用 `v2.0.0`，正文按版本号后列出本次 schema、功能、并发与体验修正。
- 推送版本 tag 使用不带 `v` 的 `2.0.0`；`.github/workflows/release.yml` 会重新构建并校验版本，随后上传 `main.js`、`manifest.json` 和 `styles.css`。
- GitHub Release 不上传 ZIP、数据库、备份、Vault 内容或其他构建目录文件。

## X1 交错修复与 schema 审查（工作区补充）

- `DatabaseManager` 使用控制面串行队列统一保护写入排空、备份、恢复、重开和关闭；插件的数据目录
  创建、载入、迁移、切换、备份、恢复和重开也通过同一条操作队列，旧服务先排空并关闭后才发布新 API。
  恢复的源校验、`.incoming` staging、安全快照和最终替换都在同一控制锁内完成；完整 ZIP 导出也在
  控制锁内生成，避免双击导出争用同一个临时文件。
- 属性/标签面板、CSV 表头切换和保存响应增加请求序列、编辑代际与卸载保护；旧响应不会覆盖较新的
  本地草稿。恢复 ZIP 拒绝重复条目、越界中心目录/本地偏移、名称不一致、长度/CRC 不匹配和路径穿越；
  目录型恢复在 SQLite 复制前后比较文件指纹，检测到 TOCTOU 变化即拒绝安装。
- 旧 `attributes`/`tags` 草稿仍可恢复，但统一进入 `taxonomy` 页面；`taxonomy` 是当前唯一主导航入口。
  历史迁移的旧 `RuleHistoryModal` 外壳已移除，保留文件仅作 re-export，不再产生第二个关闭入口。
  安全说明同步写明：普通功能不联网，只有用户主动调用可选 AI 时才通过 `requestUrl` 访问用户指定端点。

### schema 冗余字段结论

本轮只读核对 schema、迁移、Repository、备份和测试后，暂不删除 `category_definitions.necessity`、
`pattern`、`is_big_ticket`，也不删除流水和规则上的分类显示快照。前三个字段虽已弃用 UI，但仍被
schema 11→12 迁移、schema 校验、旧备份兼容和 `preserveLegacyAttributes` 读取；流水/规则快照用于
保留历史显示与规则语义。现在删除需要 schema 13 的表重建、旧备份兼容层和完整迁移回滚门禁，风险大于
收益。后续若要清理，必须单独设计 schema 13、创建保护备份、迁移旧备份并通过隔离 Vault 验证；本次
X1 仅停止新的 UI 编辑入口并将字段标记为兼容/弃用。另发现 `transactions(month)`、现金/理财余额
和固定资产月份索引属于现有复合索引或主键的前缀，作为 schema 13 的性能清理候选保留，不在本次
无查询计划和回滚证明的情况下删除。
