## v2.1.0 金额规则与实际流水合并（原本地标记）

日期：2026-10-18。状态：本地代码与构建更新，未创建 tag/GitHub Release，未部署正式 Vault。

### English

- Existing exact-match rules can optionally require an exact transaction amount. Amount-specific rules win before unrestricted rules; each tier retains counterparty+item > item > counterparty.
- Item and counterparty summaries support actual merging, one result per fully selected eligible group. All rows must resolve to one unique rule using their current draft names or the complete rewritten names.
- Confirmation updates the draft. Saving replaces the sources with a new first-day transaction, sums minor units, adopts rule-defined fields, and unions tags. The plugin offers no split-back operation.
- Schema 13 / backup format 10 preserves old rule IDs, defaults old rules to unrestricted amounts, and accepts backup formats 8/9.

### 中文

1. 金额规则：可选精确金额，与现有商品/交易对手条件组合；两位小数输入，整数分比较，限定金额优先。
2. 实际合并：商品/交易对手汇总增加行按钮和完整组选中的批量入口；同组至少两笔、同月同类型且唯一命中同一规则。
3. 合并结果：新建流水身份、日期为当月 1 日、金额累加、分类和名称遵循规则；未定义字段留空、标签取并集。
4. 草稿与保存：原生预览 Modal 说明不可拆分还原；确认不写库，保存在同一月份事务中校验 revision、来源、金额及标签，再替换来源并记审计。
5. 兼容：schema 12 先确认保护备份再升级，不清理既有属性和标签；旧规则金额为空。备份恢复支持格式 8/9/10。

### 数据与行为边界

- 不提供自动合并、跨月合并、只按金额匹配、金额区间、历史规则绑定或拆分恢复。
- 普通规则应用仍只解析一轮；合并专用解析接受原条件或完整重写结果，金额条件不放宽。
- 保存前可放弃并重载整个草稿。保存后记录数和日期统计以合并结果为准；每个并集标签统计整笔金额。
- 合并后的手工编辑和删除属于普通草稿编辑，审计分别保留确认时与最终结果。之后应用规则使用累计金额。
- 原有 `docs/logs/maintenance-audit-2026-10-01.md` 及索引改动保留，未把维护候选扩展为本次重构。

## v2.2.0 金额区间规则（原本地标记）

日期：2026-10-23。状态：本地实现，未创建 tag、GitHub Release 或公开发行。
当前正式发布版仍为 v2.0.0；本次同时包含此前未单独发布的 v2.1.0 精确金额与实际合并。

### 功能与设计

- 金额条件支持不限、等于、低于、不超过、高于、至少、双边区间；两端可独立包含或排除。
- 同一平台/商品可配置 `<2.00`、`[2.00,50.00]`、`≥100.00`，中间空档保持未命中。
- 精确金额 > 区间 > 不限金额，同档组合 > 商品 > 交易对手；精确价格可作为区间内的例外。
- 同一文字条件的两个区间只要交集非空就拒绝保存，并提示冲突行和交集。
  等价写法使用相同规范条件键，重复条件由 Repository 与 SQLite 唯一索引共同保护。
- 已有规则表的条件使用紧凑按钮，在原生 Modal 编辑；新建窗口直接设置方式和端点。
  非法小数保留原文，清空必填金额、空区间、反向边界和不安全整数均阻止确认。
- 匹配、覆盖统计、影响预览、重写链和实际合并共用整数分边界。同一区间不同价格可合并；
  合并后按累计金额重新匹配，仍不提供拆分恢复。
