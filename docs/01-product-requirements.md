# 01 产品需求

> 文档角色：开发与维护。产品叙事以[产品理念](12-product-philosophy.md)为准；本文件
> 负责把原则转换成当前需求、支持范围和用户可见行为。用户操作请读
> [用户指南](02-user-guide.md)。

## 语言与数据边界

- 插件通过 Obsidian `getLanguage()` 跟随当前应用语言；`zh-*` 使用中文，其他
  语言回退英文。
- 设置、编辑、分析、导入、确认提示、系统文件选择器和无障碍文本均使用同一语言。
- 内置业务枚举只翻译显示标签，schema 10 与数据库原值不混用；schema 9 仅通过受保护的在线迁移进入 schema 10。
- 用户创建的账户、分类、交易对方、商品和流水说明始终按原文显示。

## 产品原则到需求的映射

完整的产品叙事、用户问题和功能取舍见[产品理念](12-product-philosophy.md)。本文件
只保留对实现有约束力的映射，避免在每份技术文档中重复解释“为什么每月一次”。

| 产品原则 | 当前需求约束 |
| --- | --- |
| 每月集中 | 账单导入是主入口；手工流水只用于纠错、补漏和特殊交易 |
| 统一事实 | 账户、流水、借款、理财、固定资产、分类和规则进入同一 SQLite 事实层 |
| 例外优先 | 优先暴露未分类、冲突、缺口和对账差额，不要求逐笔人工核对 |
| 可解释 | 分析复用统一领域计算，结果可以回到分类、商品和流水 |
| 用户掌控 | 批量修改先预览再确认；备份、恢复和迁移不静默覆盖数据 |

## 当前支持边界

AssetTrack 是个人使用的桌面版 Obsidian 财务结算插件。当前实现已经具备月度账单
导入、统一 SQLite 事实层、资产对账、规则治理、分析和本地备份；月度结算工作台、
导入批次元数据和覆盖完整性诊断属于后续演进方向，不能在当前文档中当作已实现功能。

## 主要任务

- 以月度账单导入建立本月流水事实，并通过映射和质检统一异构支付平台的字段语义。
- 处理分类、商品名称和匹配规则，暴露冲突、未覆盖和需要人工确认的历史语义。
- 补充月份现金、理财、借款区块和固定资产状态，用资产闭环检查流水完整性。
- 使用分级质检、revision 和单事务避免错误覆盖：错误阻止保存，安全问题以警告保留。
- 在分析年度和月度页查看来自同一事实层的资产与消费趋势，并保留向下追溯的路径。
- 手动创建完整备份，并在恢复前验证候选数据。
- 手工编辑仅承担现金消费、账单缺失和特殊交易的补录与纠错，不作为日常高频记账主流程。

## 产品非目标

- 不把每天逐笔记账、每日预算、实时余额提醒或连续打卡作为主流程。
- 不为每个支付平台建立独立交易表、计算口径或分析页面。
- 不用自动分类掩盖规则冲突、导入缺口或资产对账差额。
- 不让 Markdown、图表、缓存、导出或 AI 输出形成第二套财务事实。

## 初始化

- 新安装不预设数据目录。
- 用户在设置中通过 Obsidian 1.13 原生 folder control 选择 Asset-track 数据目录。
- 数据库固定为 `<数据目录>/accounting_system.db`，保护备份位于
  `<数据目录>/backups/`。
- 输入目录不创建文件；用户必须显式创建新数据库或载入已通过只读校验的数据库。
- 初始化完成前 ItemView 只显示设置引导，不访问 Repository。
- 新数据库只创建默认现金和默认理财两个账户。
- 切换数据目录必须明确选择迁移当前库或载入目标库，不得覆盖目标数据库；
  失败时继续使用原数据库和原设置。

## 界面

顶部主栏固定为：

```text
分析 / 记录 / 配置
```

主栏下方按当前主页面显示第二层导航：分析为年度 / 月度；记录为资产账户 / 流水 / 借款 /
固定资产；配置为数据健康 / 分类定义 / 匹配规则 / 商品总览。没有可选
年份或月份时，分析页不显示对应的筛选控件；存在筛选控件时与分析子导航保持同一行。
记录和配置的导入、规则应用、放弃并重载及保存按钮位于当前子页面顶部的摘要下方，操作结果
使用 Obsidian Notice 提示，不在编辑表格中插入操作 callout。

流水页按四个独立区块编辑：资产账户包含现金和理财账户，流水包含账单导入、规则应用和
逐笔/汇总视图，借款包含本月可见的全局借款事实，固定资产包含月度固定资产记录。每个区块
分别提供“放弃并重载”和保存按钮；保存只写当前区块，同时携带月份 `revision`，借款额外
携带借款事实 `debt_revision`。每个区块是独立页面事务；切换流水子页、主 tab、月份或创建月份
前，如果当前区块有未保存修改，必须先选择保存或放弃。固定资产在创建月份时自动继承上月仍在用或闲置的记录，现金、
理财不会静默继承，借款也不复制为月度快照。

流水仍包含支出、收入、代付、加仓和提现五类独立编辑区。类型由编辑区固定，不显示可编辑
类型列。每个编辑区独立编号，新建流水从该分块末尾继续编号；新建支出或收入必须由用户
主动选择分类。系统按月份筛选全局 `debt_manager` 事实，显示本月底仍未还、当月新增和当月
还清的借款；用户在对应月份新增借款或勾选本月还清。

账单导入提供增量追加全部与覆盖当前流水草稿两种模式，入口位于流水子页顶端。系统不替
用户判断重复账单；汇总视图只聚合展示，SQLite 始终保存逐笔流水。交易对方与商品分别保存；
交易对方作为流水、历史统计和规则条件字段；匹配规则按收支类型和商品/交易对手三种精确作用域匹配，固定优先级不开放编辑。

月度分析中的“分类与上月对比”只使用一张横向图：分类旁直接显示增减金额，
柱形右侧分别显示上月和本月实际金额，不在图外重复展示变化标签。“异常与变化”
按分类合并上月和近三月基准，固定显示分类、当前金额和异常情况三列；大额支出
使用商品、金额两列的紧凑中文表格。异常表使用固定列宽，长说明自动换行且内容
居中，不应产生横向滚动条。月度对账位于顶部资产环比之后，只显示对账差额及
“少收入、少支出、平账”状态；差额绝对值不超过当前设置的平账容差时标记为平账。

### 多源账单统一设计

不同支付平台对收支方向使用“付款、支出、收入、转入、转出”等不同值。系统不
根据文字猜测资金语义，而是强制用户把源文件中的每个收支值映射为支出、收入、
代付、加仓、提现或忽略。这样做把多源账单在进入草稿前统一到同一套财务口径，
避免平台字段差异静默改变资产和对账结果。

代付允许使用支出类分类，并在逐项表和汇总展开中显示分类选择；加仓和提现不使用分类，
隐藏交易对手和商品，只显示账户与金额。保存时加仓和提现的分类会被清空，代付分类则按
支出类分类校验并参与分类净额统计。

交易状态同样不使用预置选项：选择状态列后，界面读取该文件中的实际不同值，再
由用户勾选允许导入的状态；空状态显示为“（空状态）”，新映射默认允许导入空状态。
日期列缺失或单元格为空时使用当前月份 1 日；非空日期无法解析、金额为空或非数字、
收支值未映射的行显示为无效并从预览中排除。空商品、零金额和缺少分类的行保留，
在月流水保存时显示警告。

配置页的数据健康直接显示商品-分类冲突处理表，不再使用问题卡片或多个冲突面板；表格按
`issue_filter=conflict` 加载，筛选变化后自动刷新。商品总览独立提供收支、分类、商品和时间筛选，
用于创建规则、编辑商品和编辑分类。具体商品时间线、商品名称修改和分类迁移使用浮动窗口；
推荐与历史统计只读取已保存月份，商品历史按收支类型和规范化商品/交易对手聚合。规则按收支类型和
三种精确作用域匹配；规则诊断仍由后端模型保留，用于保护历史回溯，但当前数据健康只显示商品-分类冲突。
回溯和商品统一只修改对应字段并携带月份 revision，分类和规则分别保存并分别校验 revision；通用规则、分类描述、
流水来源、理财流水账户和操作审计属于 schema 10 的字段或索引；加仓、提现可选择理财账户，月度分析按账户展示本金、
市值、流动资金、仓位、收益率及与上月的变化。

关闭有未保存内容的 ItemView 时，如果用户取消放弃，插件在当前会话内重新打开同一
编辑模式并恢复月流水、借款区块、规则、revision 和 dirty 状态。恢复状态只存在内存，
不写入数据库、
插件设置或 workspace layout；外部 revision 变化仍会阻止旧草稿覆盖。

## 明确不支持

- 自动备份。
- Markdown/SVG 报告生成。
- AI 分类、银行同步、移动端和多设备并发写同一 SQLite。
- 移动端和不具备 `node:sqlite` 的旧 Obsidian 桌面安装器。

## v1.7.0 当前显示、分析与规则工作台

- 设置页提供基础货币、标准/会计金额格式、平账容差和大额支出阈值。
- 所有金额使用 `Intl.NumberFormat`；收入、提现显示正向，支出、代付和加仓显示负向，数据库仍保存绝对金额。
- 年度页并列展示年末总资产、年末净资产、年末现金和年末借款；年度理财本金不再作为独立展示项。
- 年度页提供最近 12 个有数据月份的只读周期消费面板，按商品汇总，不预测下一次扣费或订阅状态。
- 数据健康直接显示商品-分类冲突表；商品编辑和分类迁移均使用已保存月份与 revision 校验，不按多数分类自动改写历史。
- 流水按出账、入账、理财分 Tab，并支持逐项、商品汇总、交易对手汇总、多选、批量预览和操作日志；
  规则支持商品、交易对手和组合三种作用域，固定优先级为组合 > 商品 > 交易对手。
- 分类定义支持描述；AI 分类是可选建议层，Key 使用 SecretStorage，结果按状态预览、确认、重试，不能自动创建规则。
- 借款作为月流水页内区块管理，自动继承上月未还；新增、还清和当月借款金额调整会进入
  流水顶部对账差额的实时计算。
- 加仓和提现不显示分类列或“无需分类”占位；代付与支出一样显示分类并允许互转。商品汇总
  不显示最近日期，保留类型、商品、次数、总金额、分类和操作，并支持按类型和分类排序。
- 普通表格统一使用语义列宽、正文小字号、上下居中和长文本换行；操作列使用“操作 / Actions”
  不可排序表头，所有可见表头使用统一按钮式视觉，只有实际可排序表头响应交互；流水虚拟编辑网格
  与其他表格一样自适应宽度，仅保留纵向虚拟滚动。

## v1.7.0 性能基线与数据规模

- SQLite 写入连接的锁等待上限为 5000 毫秒；这是等待其他写入者释放锁的上限，不是查询执行超时。
- 以 50,000 条历史流水、200 个商品组和 20 条规则组成的合成数据作为回归基线：年度分析应在 2 秒内完成，商品总览与规则分析连续执行应在 8 秒内完成，整组 SQLite 性能用例的时限为 20 秒。
- 50,000 条流水的前端分块行号预计算应在 250 毫秒内完成；这属于 JavaScript 计算基线，不等同于 SQLite 查询基线。
- 可能触发较长同步工作的入口包括数据健康/规则工作台、商品总览、规则保存后的统计刷新和切换月份后的月度分析；月度保存的主要变量是当前月份的流水数量。
- 以上是自动化回归门槛，不承诺所有设备上的界面响应 SLA；`DatabaseSync` 的同步读取和写入仍可能短暂占用 Obsidian 主线程。

Asset Track 项目已通过 Community Plugins 审核；v1.7.0 继续采用纯 TypeScript
运行链并生成标准三文件。历史版本的行为和验证状态以对应 release 日志为准。

## v1.7.0 Obsidian 1.13 兼容要求

- 最低 Obsidian 版本提升为 1.13.0；安装和更新前要求用户使用当前最新的 1.13.x
  桌面版，避免设置 API 和桌面运行时版本不一致。
- 设置页迁移到 `getSettingDefinitions()`，数据库目录使用原生 folder control；备份恢复
  和账户编辑保留为声明式设置页支持的自定义页面。
- 插件不再使用 `getAllLoadedFiles()`、`getFiles()` 或 `getMarkdownFiles()` 枚举 Vault；
  数据目录仍只允许用户选择的 Vault 相对路径。
- 目录输入只保存设置页内的待确认草稿，创建、载入或迁移成功后才写入 `data.json`。
- schema 10、数据库路径、财务计算口径不变；schema 9 首次打开会先创建保护备份并执行 9→10 迁移，备份格式随新字段升级。

v1.7.0 的真实 Obsidian 门禁和发行状态以 `docs/logs/release-v1.7.0.md` 为准。
