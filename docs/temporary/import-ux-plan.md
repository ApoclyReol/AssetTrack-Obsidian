# 导入账单体验优化临时计划

> 状态：进行中。本文是本轮改动的工作计划，不是长期产品规范；完成导入流程后再决定是否合并到正式文档。

## 范围

本轮只优化“导入账单”流程。流水编辑、月度工作台、规则、分析、配置等其他界面保持现状。

保留既有业务边界：

- 导入路径仍然是“选择账单 → 确认映射 → 预览 → 加入当前草稿 → 用户保存”。
- 追加模式仍然不自动去重。
- 替换模式仍然只替换当前流水草稿，不直接写入数据库。
- 原始账单来源和过滤原因继续保留。
- 不在本轮引入自动语义猜测、自动去重、平台专用模板、批次覆盖率模型或自动保存。

## 当前阶段结果

- 导入弹窗已按“文件概览 → 导入方式 → 必填字段 → 可选字段 → 收支/状态 → 预览”重新组织。
- 文件结构检查会先判断表头是否合理；遇到账单导出前存在说明、汇总或备注段落时，在同一界面显示表头确认区，不再弹出新窗口。
- 表头确认区支持候选行、原始行号、原始内容预览、手动输入行号和重新读取；确认后会按所选行重新生成字段映射与预览。
- 解析保留源文件行号，因而选择第 8 行作为表头时，导入记录仍能准确回溯到源文件的实际行号。
- 字段下拉框旁显示用途、示例值和空值数量；收支和状态显示原始值数量。
- 收支列中的空值会显式列出，必须选择业务结果或“忽略”，避免用户无意中静默丢失这类行。
- 预览显示接受、过滤、日期默认值、错误/警告、接受日期范围、类型汇总和过滤原因。
- 追加与替换显示影响范围；接受行数为 0 时不能应用到草稿。
- 保留键盘焦点陷阱、Escape、ARIA 标签、中文/英文文案和主题变量约束。
- 已验证：`npm run typecheck`、`npm test -- --run`、`npm run lint`、`npm run build`。

## 全局验收约束

- 新增交互必须支持键盘操作、焦点可见、Escape 和屏幕阅读器状态播报。
- 文案必须同时覆盖中文和英文，并说明“发生了什么、影响是什么、下一步是什么”。
- 样式使用 Obsidian 主题变量，兼容窄窗口和不同主题。
- 不改变财务计算口径，不绕过预览确认，不增加自动写库行为。
