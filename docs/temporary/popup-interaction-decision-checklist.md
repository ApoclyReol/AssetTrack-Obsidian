# 界面交互整理与待决策清单

> 历史设计及批注记录：以下保留当时的决策状态。功能已实装并获用户验收；当前状态见 [v2.2.0 发布记录](../logs/release-v2.2.0.md)。

日期：2026-10-24。修订：第二版，已吸收用户高亮批注及正文补充。检查基线：v2.1.0，源码提交 `8af22aa`。

本文按实际页面与功能组织弹出式交互问题。**用户已明确的决定已写入对应条目；具体模板、反馈形式和未批注事项仍待决策。全部功能均未实施。** 本次只修订清单，不修改当前业务规则。

## 使用范围

- 以鼠标操作为主，关注误关闭、操作步骤、页面上下文、信息呈现和保存结果。
- 不纳入键盘误触、默认焦点、快捷键、焦点循环与读屏播报等议题；不要求移除已有支持。
- “已确认”指源码中可以确认的行为或缺口；“优化建议”是设计取舍，不等于功能错误；“待实测”需要在真实 Obsidian 中复现。
- 顺序分为“先处理”“随后”“可后置”，只是讨论建议。没有当前证据支持的问题不补造；没有独立弹窗的页面不强行新增弹窗。
- 后续按原编号继续决策，不重新编号。新增对账悬停说明 A-02；T-05 改为记录已确定的“删除替换标签”，不再讨论该功能的选择器。
- “已定”仅代表用户已同意方向或范围；“候选”不代表已经批准。未批注条目继续待决策，不能因统一模板而自动接受功能改动。

## 0. 统一设计语言：已定要求与候选模板

### 0.1 用户已明确的要求

- 以鼠标交互为主。编辑窗口采用 G-01 的关闭保护，每个窗口的动作与按钮要非常明确。
- 先完整提取现有组件的内容与行为，再统一设计语言和模板；本版提供候选，不直接改功能。
- 普通确认与危险确认分开；提示反馈按场景列清单后继续决策。
- 分析明细保留 Modal；对账问号改为 hover；按钮受限原因采用不改变按钮尺寸的小问号快速 hover。
- 合并入口改“合并此组”，删除合并前逐笔明细。批量字段也要有预览，与合并统一设计语言。
- 批量标签删除“替换”，只保留添加与移除，并采用复选框多选。
