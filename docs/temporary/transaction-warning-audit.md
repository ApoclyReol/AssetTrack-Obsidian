# 流水警告、错误与异常审计（临时）

> 审计日期：2026-09-14。本文只记录当前代码的实际行为，不改变任何判定规则；下一轮可以按表格逐项决定“保留、降级、合并或移除”。

## 先给结论

- “未分类”目前不是阻止保存的错误，而是**不阻止保存的警告**。
- 支出和收入没有有效分类时会产生分类警告；代付为空分类是允许的；加仓和提现不应有分类。
- 导入阶段的“日期无法识别、金额无法识别、收支值未映射、跨月、状态未选、忽略类型”主要是**过滤结果**，表示这些行不会进入预览，不等同于流水页的质检错误。
- 导入预览会把接受行先交给流水质检，但会隐藏“空分类/未匹配分类”这类导入后可整理提醒；加入草稿后仍会重新执行完整质检。
- 当前分析异常是只读提示，不阻止保存；对账差额是结果状态，不应和单行流水错误混在一起。

## 1. 导入文件结构和映射错误

这些问题发生在读取文件或生成预览之前，属于“无法继续当前导入”的流程错误：

| 条件 | 当前反馈 | 是否进入预览 |
| --- | --- | --- |
| 文件扩展名不是 CSV/XLSX/XLS | 要求重新选择支持的账单文件 | 否 |
| 没有可读取的工作表 | 要求检查工作簿 | 否 |
| 工作表没有可识别表头 | 要求选择正确工作表或表头行 | 否 |
| 表头缺失、重复或指定行无效 | 要求整理文件或调整表头行 | 否 |
| 必填字段未选择或选择的列不存在 | 要求重新选择日期、商品、金额、收支列 | 否 |
| 可选字段选择的列不存在 | 要求修正该可选映射 | 否 |
| 选择了状态列但没有勾选任何状态 | 要求至少选择一个状态 | 否 |

这类错误阻止的是导入操作本身，不是对已存在流水的保存。

## 2. 导入行过滤结果

当前 `previewCsv` 按顺序处理每一行。被过滤的行会记录原始行号、原因和原始单元格，并不会进入草稿：

| 原因 | 触发条件 | 用户应如何理解 |
| --- | --- | --- |
| 状态过滤 | 有状态列，但该行状态未被勾选 | 本次选择范围主动排除了该行 |
| 忽略类型 | 原始收支值被映射为“忽略” | 用户主动选择不导入该类流水 |
| 收支值未映射 | 原始收支值没有明确映射到允许类型 | 该行不能安全判断业务方向 |
| 日期无法识别 | 非空日期无法按支持格式解析 | 该行没有可靠日期，暂不导入 |
| 跨月 | 日期解析成功，但不属于目标月份 | 该行属于其他月份，不进入当前月 |
| 金额无法识别 | 金额为空或不是支持的数字格式 | 该行没有可靠金额，暂不导入 |

补充：日期列缺失或日期单元格为空时，当前实现会使用目标月份 1 日，并在预览中以“日期补为月初”计数；这不是错误，但需要用户导入后检查。导入金额会以绝对值保存，收支方向由类型映射表达，因此负号不会形成流水页的“金额不能为负数”警告。

## 3. 流水质检：错误与警告

`validateTransactions` 的结果会在加载、编辑、导入预览和保存前后使用。错误会阻止保存；警告不会阻止保存。

### 3.1 当前会阻止保存的错误

| 字段 | 条件 | 当前影响 |
| --- | --- | --- |
| 日期 | 日期无法识别 | 阻止保存 |
| 日期 | 日期不属于当前月份 | 阻止保存 |
| 金额 | 为空、非数字或无法识别 | 阻止保存 |
| 金额 | 小于 0 | 阻止保存 |
| 收支 | 不是支出、收入、代付、加仓、提现之一 | 阻止保存 |
| 分类 | 使用已停用分类 | 阻止保存 |
| 分类 | 分类的收支类型与流水不匹配 | 阻止保存 |

### 3.2 当前不会阻止保存的警告

| 字段 | 条件 | 当前含义 |
| --- | --- | --- |
| 商品 | 非加仓/提现流水的商品为空 | 建议补充说明，便于后续查找和分类 |
| 金额 | 金额为 0 | 提醒确认是否只是占位流水 |
| 分类 | 支出或收入没有有效分类 | 仍保留流水，等待用户后续整理 |
| 分类 | 代付填写了不存在或无效分类 | 代付可以为空，但填写后必须能对应有效支出分类 |
| 分类 | 加仓或提现填写了分类 | 提醒理财流水不参与普通消费分类 |

其中，“支出/收入未分类”是警告，不是错误，不会阻止接受行加入草稿。现在导入预览不再把它列为导入警告；导入页改为说明分类需预先配置、无法匹配的分类会重置为“未分类”。接受行进入草稿后仍按行生成 `?` 标记，提醒用户后续整理。

## 4. 保存和展示流程

当前流程是：

```text
读取或编辑草稿
→ 运行流水质检
→ 错误存在：不调用保存 Service
→ 只有警告：允许保存
→ 保存后再次质检
→ 在行号标记和流水页一行提醒中继续显示未解决警告
```

当前已调整为：流水页不再堆叠问题汇总框，只保留一行数量和保存影响提醒；问题原因仍显示在具体行号旁的 `!` / `?` 标记中，避免用户必须从长列表逐条阅读。

## 5. 月度分析中的异常和对账状态

这些不是流水保存错误：

| 类型 | 当前条件 | 当前影响 |
| --- | --- | --- |
| 分类变化异常 | 与上月或近 3 月均值的变化绝对值超过 `max(100 元, 历史均值 × 30%)`；大额分类不进入该比较 | 只读分析提示 |
| 周期项缺失 | 周期分类在历史窗口出现过，但本月没有出现；单月比较至少出现 1 次，三月比较至少出现 2 次 | 只读分析提示 |
| 新大额商品 | 当前商品金额达到大额支出阈值，且过去 12 个月没有出现 | 只读分析提示 |
| 无连续上月基准 | 没有上月现金/资产快照 | 对账不可比较，不伪造平账 |
| 平账 | 对账差额绝对值不超过设置的平账容差 | 结果状态，不是错误 |
| 正差额 | 实际净支出高于理论消费，显示“少收入” | 结果状态，提示检查漏记收入、重复支出或现金快照偏高 |
| 负差额 | 理论消费高于实际净支出，显示“少支出” | 结果状态，提示检查漏记消费、理财类型或现金快照偏低 |

月度分析中的大块对账解释面板已移除，保留摘要数字；补充说明改放到流水页面“对账差额”旁的 `?` 说明中，正差额、负差额、平账和无基准分别解释。

## 6. 本轮已落实与下一轮建议

本轮已落实：

- 导入预览只隐藏空分类和无法匹配分类的非阻断提醒；日期、金额、收支类型、停用分类、类型不匹配等其他检查保持原行为。
- 导入页增加分类规则说明：分类不是必填字段，分类定义需先在系统配置中存在，无法匹配的文件分类会重置为“未分类”。
- 接受行加入草稿后重新执行完整质检，未分类流水仍保留行号旁的 `?` 标记。
- 统计默认仍使用近 5 年；分类迁移、商品名修改、交易对手修改等历史修改入口使用全部已保存历史。
- 分类配置区说明停用分类前应先迁移流水条目、处理规则引用，再删除分类。

下一轮建议单独决策的项目：

1. **未分类提示合并**：保留行内问号和总数，但将多条“分类为空”合并为“有 N 条待补分类”，点击后再定位具体行。
2. **导入预览降噪**：日期/金额无法识别继续作为过滤统计；未分类只显示为“导入后待整理”。
3. **商品为空与金额为 0**：继续作为可保存提醒，但默认只显示汇总，不逐条弹出 Notice。
4. **真正阻断项保持不变**：无法识别日期、金额、流水类型、停用分类和分类类型不匹配仍需修正。
5. **分析异常保持只读**：不把消费波动、周期项缺失或对账差额变成保存错误。

本审计没有改变上述行为，只为下一轮警告简化提供当前代码和用户语义之间的对照。
