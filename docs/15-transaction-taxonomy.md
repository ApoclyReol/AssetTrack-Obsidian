# 15 流水标签与分类属性

> 文档角色：当前 schema 12 的产品、数据和维护边界。迁移、备份和分析实现以本文与
> `src/database/schema.ts`、`src/database/AssetTrackRepository.ts` 为事实入口。

## 一、三个独立概念

| 概念 | 说明 | 绑定对象 | 是否影响财务总额 |
| --- | --- | --- | --- |
| 分类 | 流水属于哪类收支，由用户或匹配规则确定 | 流水、分类定义 | 影响分类汇总和现有财务口径 |
| 属性 | 描述分类的特征，例如必要、周期、大额 | 分类与属性选项 | 只改变结构分析视角 |
| 标签 | 描述某笔流水跨分类的主题，例如旅行 | 流水与标签定义 | 只改变标签分析视角 |

分类、属性和标签不是同一套值。导入和匹配规则只处理分类及既有字段，不会自动给流水
添加标签。属性组和标签都可以为空；没有属性或标签是正常状态，不属于数据错误。

## 二、数据库模型

schema 12 新增五张表：

- `attribute_groups(group_key, name, selection_mode, is_active, sort_order)`；当前选择模式为
  `single`。
- `attribute_options(attribute_key, group_key, name, is_active, sort_order)`；同一组内名称唯一。
- `category_attributes(category_key, attribute_key)`；分类与属性选项的多对多关系，Repository
  校验每个分类在同一组最多一个选项。
- `tags(tag_key, name, description, color, is_active, sort_order)`；标签定义独立于分类和规则。
- `transaction_tags(transaction_id, tag_key)`；流水与标签的多对多关系，主键为两列组合。

所有关联使用稳定 key 和外键，不把标签数组写入 SQLite 文本列。`Transaction` 读写接口以
`tag_keys: string[]` 暴露关联，保存月份时会在同一事务中重建 `transaction_tags`，并同时
写入已有操作日志。月份保存仍使用 `expected_revision`；属性配置和标签配置分别使用
`attribute_revision`、`tag_revision`。

## 三、默认值与迁移

新库预置三个可删除的属性组：必要性、消费频率、支出规模；组内选项对应旧的必要性、频率和
分类大额标记。新库只预置一个可删除的“旅行”标签。用户可以移除这些定义。

打开 schema 9、10 或 11 数据库时，设置页先通过只读检查展示分类数、流水数及三类旧属性影响。
用户有三个选择：

1. **保留并迁移**：在迁移事务中把旧必要性、消费频率和大额分类标记转成属性关联；
2. **清除并迁移**：建立新的属性组和选项，但不创建旧属性关联；
3. **取消**：不打开旧数据库，原文件保持不变。

确认后才创建 `backups/before-schema12-*.db` 保护备份，并在现有 9→10→11 链之后执行
11→12 事务；迁移会校验行数、外键和 SQLite 完整性，失败自动回滚。自动打开 ItemView
不会绕过这个确认门槛。

完整 schema 12 备份格式为 9，新增五张表的 CSV 和摘要。旧 schema 11 完整备份格式 8 仍可
只读校验、创建临时迁移副本并按同一保护迁移路径恢复；失败不会覆盖当前数据库。

## 四、编辑流程

### 分类属性

“配置 → 分类定义”中的名称、收支类型和颜色可以直接在表格内修改；“编辑”入口主要处理说明、
属性选择、迁移历史流水或移除分类。必要性、消费频率和大额不再作为分类字段编辑。属性列显示
紧凑的属性值，操作列仅有“编辑”入口，在同一窗口内按组单选属性、迁移历史流水或移除分类。
保存分类属性前会确认历史影响；保存后，引用这些分类的
历史月份会增加 revision，重新打开分析即可看到新的属性口径。

### 属性和标签定义

“配置 → 分类属性”是一个左右分栏页面。左侧管理属性组和属性值，右侧管理标签；宽度不足时
自动上下排列。每一侧都提供新增和自己的保存按钮，属性保存不会提交标签草稿，标签保存也不会
提交属性草稿；切换配置子页或离开页面时，如有未保存修改会提示保存或放弃。属性组和属性值使用紧凑
标签样式，标签使用独立表格；每个定义只保留一个“编辑”入口。
编辑窗口内选择移除后，会明确说明原有属性或标签将清理，或转移到哪个目标定义，并在窗口内二次确认；属性值
只能转移到同组的其他属性值；属性组整体转移会将原组所有值合并为一个目标值，并替换受影响分类
在目标组中的原选择，也可选择清理原组关联。确认先更新配置草稿，保存时
在一个数据库事务内检查定义版本、引用集合及目标定义并执行修改。若本次保存清理或转移历史
关联，仅在保存前创建一次保护快照。界面不展示 sha、完整路径、月份等内部明细，只说明待确认的
清理或转移动作。

### 流水标签

逐笔表的出账和入账流水用紧凑标签显示当前值，点击“编辑”打开独立弹窗；标题显示为“编辑
<商品> 的标签”，并预先勾选当前标签；理财流水不展示标签入口。
标签可以跨分类且一笔流水可以选择多个标签。商品
汇总和交易对手汇总的多选操作提供“添加、移除、替换”三个预览动作。确认只更新当前月份草稿，
点击“保存流水”时才写入数据库和操作日志。导入、匹配规则和 AI 分类建议不会自动打标签。

## 五、分析口径

月度和年度支出结构同时提供分类、属性、标签三个视角：

- 分类视角保持现有支出、代付抵扣、收入、加仓和提现口径；资产、对账、储蓄率公式不变。
- 属性按属性组展示，每组可选项分别统计。没有属性的分类不会被伪造为错误。
- 标签按标签独立统计总额、流水数、分类构成和年度逐月趋势。标签允许重叠，同一笔流水完整计入
  它拥有的每个标签，因此标签金额不能相加推导总支出；界面会持续提示这一点。
- 月度分类、属性和标签视角在弹窗展示相关流水；年度分类成本不提供跳转按钮。分析为空时显示
  正常空状态，而不是健康度错误。
- 月度相关流水依次显示日期、商品、交易对手、分类和金额；收入分析逐笔显示收入项目、分类、金额和合计。

大额支出不再由设置中的金额阈值推断；历史分类大额标记迁移为“支出规模 → 大额”属性。异常
变化继续使用分类的固定比较规则，财务总额和对账公式不读取属性或标签。
旧分类列 `necessity`、`pattern`、`is_big_ticket` 及年度“总资产支撑月”指标均归入兼容/弃用
字段：运行中的结构判断只读属性关联，年度界面不再展示总资产支撑月。

## 六、维护与验证清单

- schema 9/10/11 的保留、清除、取消、失败回滚和旧备份恢复均需测试；测试必须确认原文件未被
  只读检查改变。
- 月份 revision 冲突、出账/入账标签保存、理财无标签入口、批量标签预览重放和操作日志字段必须测试。
- 属性和标签的清理、转移、外键限制、同数量引用集合变化和事务回滚必须测试；历史引用变更
  保存前应保留一次保护快照。
- schema 12 的索引也做过只读核对：`transactions(month)` 是
  `transactions(month,transaction_date,id)` 的前缀，现金/理财余额和固定资产的月份索引分别是
  复合主键或唯一键的前缀。这些是可评估的性能清理候选，但当前仍由 schema 校验和既有数据库
  兼容边界保留；删除前需用真实查询计划和 schema 13 重建迁移证明没有回归。
- 月度、年度分类/属性/标签分析应验证下钻、标签重叠不重复进入财务总额，以及 50,000 条流水
  的读取性能基线。
- 分类属性、流水标签、数据健康操作列和历史迁移的真实界面点击，按[界面回归测试协议](16-ui-regression-protocol.md)
  执行；单元测试通过不能替代标签弹窗、确认弹窗和窄窗口表格的现场验证。
